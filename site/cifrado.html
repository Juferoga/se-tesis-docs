Etapa 4 · Cifrado XOR

El mensaje comprimido se cifra con XOR

Cada byte del mensaje se combina con un byte del flujo de clave. El resultado parece ruido para quien no tiene la clave, y quien la tiene lo deshace con la misma operación.

Paso 1

Qué es XOR

XOR (se escribe ⊕) combina dos bits. Da 1 cuando los dos bits son distintos y 0 cuando son iguales.

Otra forma de verlo: el bit de la clave decide si el bit del mensaje se deja igual (clave 0) o se invierte (clave 1).

Piensa en un interruptor de luz. Si el bit de la clave es 1, alguien acciona el interruptor y la luz cambia de estado. Si es 0, nadie lo toca y la luz queda como estaba.

Detalle técnico

XOR es el «o exclusivo». Cumple x ⊕ 0 = x y x ⊕ x = 0, y es conmutativo y asociativo. Aplicado a bytes, se opera en cada una de las 8 posiciones por separado.

Paso 2

El flujo de clave se agrupa en bytes

La etapa anterior produjo una larga fila de bits, el flujo de clave. Para cifrar se toman de 8 en 8 y cada grupo forma un byte k1, k2, k3…

El primer bit de cada grupo es el más significativo (vale 128) y el último el menos significativo (vale 1).

Es como leer un número de izquierda a derecha: la primera cifra es la que más pesa.

Detalle técnico

kj = Σt=0..7 b8(j−1)+t+1 · 27−t, donde b es el flujo de clave (XOR de las secuencias 1 y 2 binarizadas con el umbral 0.5: > 0.5 → 1, ≤ 0.5 → 0).

Paso 3

Cifrar los dos primeros bytes

Los dos primeros bytes del mensaje guardan la longitud del mensaje comprimido: 173 bytes, escrita en 2 bytes con el byte más significativo primero (big-endian). Son m1 = 00000000 y m2 = 10101101.

Cada columna se cifra por separado: c = m ⊕ k. Donde la clave tiene un 1, el bit del mensaje se invierte.

Detalle técnico

173 = 0x00AD. cj = mj ⊕ kj. Los bytes k1 y k2 de la escena se calculan en tu navegador con la clave del caso (x0 = 0.123456, r = 3.999952, N = 6173).

Paso 4

Descifrar es repetir la misma operación

El receptor tiene la misma clave, así que puede producir el mismo flujo k. Aplica otra vez XOR al cifrado y obtiene el mensaje original.

Funciona porque invertir dos veces un bit lo deja como estaba: (m ⊕ k) ⊕ k = m.

Si accionas el mismo interruptor dos veces, la luz vuelve a su estado inicial.

Detalle técnico

(m ⊕ k) ⊕ k = m ⊕ (k ⊕ k) = m ⊕ 0 = m, por la asociatividad de XOR y porque k ⊕ k = 0.

Paso 5

Por qué XOR

El mismo procedimiento cifra y descifra (es involutivo). No agranda el mensaje: 175 bytes siguen siendo 175. Su costo crece en proporción directa a la longitud del mensaje.

Si el flujo de clave está equilibrado (tantos unos como ceros) y no se puede predecir, el cifrado no conserva la estadística del texto. Es un cifrado de flujo del tipo de Vernam.

Detalle técnico

El costo es O(n) operaciones de bytes. El cifrado de Vernam combina el mensaje con una clave tan larga como él; aquí esa clave larga la genera el mapa logístico a partir de la clave corta K.

Paso 6

Qué le pasa a un texto

Un texto en español usa pocos valores de byte: letras, espacios y algunos acentos. Por eso su histograma tiene picos.

Tras el XOR con el flujo, los bytes se reparten por todo el rango de 0 a 255 y los picos desaparecen.

En el modelo real lo que se cifra es el mensaje ya comprimido. Aquí se cifra el verso sin comprimir solo para que se vea el efecto.

Detalle técnico

El verso se codifica en UTF-8 (la «ñ» y las vocales con tilde ocupan 2 bytes) y se cifra con los primeros bytes del flujo real de la clave del caso.

Paso 7

Por qué dos secuencias

El flujo de clave es el XOR de dos secuencias del mapa logístico, cada una con su propio valor inicial y su propio parámetro.

Juntas tienen un estado interno de 4 × 64 = 256 bits, más que los 144 bits de la clave. Si alguien lograra reconstruir una secuencia, le faltaría la otra para obtener el flujo.

Es como una caja fuerte con dos cerraduras: abrir una no basta.

Detalle técnico

El estado es (x, r) de cada secuencia, 4 valores float64. La clave K = (x0, r, N) ocupa 144 bits en memoria y admite 2112.91 claves válidas.

Paso 8

De bytes a bits

El mensaje cifrado c tiene n = 175 bytes. Se escribe como una cadena de L = 8 × 175 = 1400 bits, w1 … w1400. Esos son los bits que se esconderán en el audio.

Como la longitud viaja cifrada en los 2 primeros bytes, el receptor solo necesita la clave para saber cuántos bits leer.

Detalle técnico

175 = 2 bytes de longitud + 173 bytes del mensaje comprimido. Los bits de cada byte se escriben del más al menos significativo.
