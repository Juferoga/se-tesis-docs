Etapa 0 · Panorama

Un texto escondido en un audio que solo abre quien tiene la clave

Este sitio explica, paso a paso, un modelo que comprime un texto, lo cifra y lo esconde dentro de una canción. Quien tiene la clave lo recupera exacto, letra por letra. Empieza aquí para ver el recorrido completo.

Paso 1

El problema: mandar un secreto sin que se note

Queremos enviar un texto escondido dentro de un audio. Quien lo escuche oye solo música; quien tiene la clave saca el texto idéntico al original.

El emisor hace tres cosas en orden: comprime, cifra y esconde. El receptor las deshace.

Como una nota en clave, doblada y metida entre las páginas de un libro: el libro se ve igual.

Paso 2 · Emisor

Primero, comprimir

Una red neuronal adivina qué fragmento del texto viene después, y un codificador aprovecha esas apuestas: lo fácil de adivinar ocupa muy poco.

El poema pasa de 928 a 173 bytes. Con 2 bytes que anotan esa longitud quedan 175.

Si alguien dice «Había una vez…», el resto casi no hace falta escribirlo.

Detalle técnico

La red es Qwen2.5-1.5B (pública). El texto se parte en 293 tokens y la red da una probabilidad a cada uno. Un codificador aritmético convierte esas probabilidades en bits: el tamaño final es casi la suma de −log2 p de cada token. Comprimir antes de esconder reduce las muestras de audio que hay que tocar. Todo está en la Etapa 1.

Paso 3 · Emisor

Luego, cifrar con la clave

Los 175 bytes se mezclan con una lista de bits que solo se puede fabricar con la clave K. El resultado parece ruido.

Esa lista sale de dos secuencias del mapa logístico, una fórmula simple muy sensible a su punto de partida.

Como un candado de combinación: el modelo es el mismo para todos, pero abre solo con la combinación correcta.

Detalle técnico

Cada valor de las secuencias se convierte en un bit: si es mayor que 0.5 da 1; si es menor o igual que 0.5 da 0. Los bits de las dos secuencias se combinan con XOR (da 1 si son distintos y 0 si son iguales) y forman el flujo de clave. Cada bit del mensaje se combina con XOR con un bit de ese flujo. Ver Etapa 3 y Etapa 4.

Paso 4 · Emisor

Por último, esconder en el audio

Un audio digital es una lista enorme de números llamados muestras. Cada bit cifrado reemplaza el último bit de una muestra: el valor se mueve una unidad entre 65 536 posibles y el oído no lo nota.

Otra secuencia hecha con la clave K elige qué muestras se usan.

Como cambiar de color 1400 granos escogidos en una playa: solo quien tiene el mapa los encuentra.

Detalle técnico

Ese último bit se llama bit menos significativo (LSB). Se insertan L = 1400 bits en un audio de M = 25 143 552 muestras, es decir, se modifica el 0.006 % de las muestras. Las posiciones salen de una tercera secuencia del mapa logístico y no se repiten. Ver Etapa 5.

Paso 5

La clave K: lo único secreto

La clave K son tres números, x0, r y N, que emisor y receptor acuerdan antes, como una contraseña. De ella salen el flujo del cifrado y la lista de muestras.

La red neuronal, las fórmulas y el programa son públicos.

Como una cerradura comercial: cualquiera puede estudiar el modelo, pero solo tu llave abre tu puerta.

Detalle técnico

En el caso de estudio, K = (x0 = 0.123456, r = 3.999952, N = 6173). Esos números no se iteran directamente: se pasan por SHA-512, que produce una cadena fija de 512 bits. De esa cadena se toman las condiciones iniciales y los parámetros de las tres secuencias. La clave ocupa 144 bits en memoria y hay 2112.91 claves válidas. Ver Etapa 2 y Etapa 7.

Paso 6 · Receptor

El receptor deshace todo en orden inverso

Con la misma clave K lee las muestras elegidas y saca los 1400 bits. Con K fabrica el mismo flujo y deshace el cifrado. Con la misma red neuronal descomprime el texto.

No necesita el audio original.

Como desarmar un paquete: primero se quita lo último que se puso.

Detalle técnico

XOR aplicado dos veces con el mismo flujo devuelve el dato original, por eso el descifrado es la misma operación. La red, con los mismos pesos y la misma configuración, recalcula las mismas probabilidades, y el decodificador aritmético reconstruye los tokens uno por uno hasta el token de fin. Ver Etapa 6.

Paso 7

Las cifras del caso de estudio

El poema «Nocturno» de José Asunción Silva, escondido en una canción:

Texto
901 caracteres, 928 bytes
Comprimido
173 + 2 = 175 bytes = 1400 bits
Audio
WAV estéreo, 25 143 552 muestras
Muestras usadas
0.006 %
Calidad
PSNR de 135.89 dB
Recuperación
exacta (SHA-256)
Detalle técnico

El audio es un WAV de 16 bits, 44 100 Hz, estéreo y 4 min 45 s: M = 25 143 552 muestras. 1400 / 25 143 552 = 0.0056 %, que se redondea a 0.006 %. El PSNR compara el audio original con el que lleva el mensaje: mientras más alto, más parecidos; 135.89 dB indica una diferencia ínfima. SHA-256 calcula un resumen de 256 bits de cada texto: el del original y el del recuperado son iguales, así que los textos coinciden byte por byte.
